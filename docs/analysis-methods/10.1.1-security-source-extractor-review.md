# Zimbra 10.1.1 security source-extractor review

This review assesses the security fixes listed in the [10.1.1 release
announcement](https://wiki.zimbra.com/index.php?title=Zimbra_Releases/10.1.1#Security_Fixes)
for deterministic Ubuntu 24.04 source extractors.  An extractor is only added
when a changed, textual package artifact has a declared public upstream source
scope.  A public upstream diff alone is not enough: the extractor must be able
to reconstruct its output from a package hunk.

## Inputs and limitation

`zm-build-print-repos.pl` from
[`maldua/zimbra-tag-helper`](https://github.com/maldua/zimbra-tag-helper) was
run with `zm-build` at tag `10.1.1`, and again at its previous release tag
`10.1.0`.  The repo lists are identical: 53 Zimbra repositories.  Of those,
only these repositories expose both tags:

```text
java-html-sanitizer-release-20190610.1
zm-admin-ajax
zm-admin-console
zm-ajax
zm-core-utils
zm-mailbox
zm-web-client
zm-zcs-lib
```

The current Ubuntu 24.04 non-patch APT metadata does not retain builds whose
versions begin with `10.1.0.` or `10.1.1.`.  Furthermore, Ubuntu 24.04 was not
a 10.1.1 GA platform.  Ubuntu 18, 20, and 22 retain the `10.1.1`
`zimbra-mbox-webclient-war` build but do not retain its `10.1.0` counterpart.
The checked-in original 10.1.0 installer manifests make the missing before
package available as a verified, host-extracted local APT source.  Run the
extractor with `--ubuntu-series 18 --local-release 10.1.0` (or the matching
20/22 series) to compare it with the retained 10.1.1 package.

This was validated with the Ubuntu 18 original package
`10.1.0.1716285217-1.u18` and the retained Ubuntu 18 package
`10.1.1.1723653022-1.u18`: the three direct `.jsp`/`.tag` artifacts which
support the security mappings reconstruct all eight textual package hunks with
no unmatched or ambiguous hunk.  The resulting source files are `restHead.tag`,
`launchNewWindow.jsp`, and `launchZCS.jsp`. The consolidated extractor also
scopes `Mail_all.js`; its seven additional 10.1.1 hunks map exactly to
`ZmComposeController.js` and `ZmComposeView.js`. Thus the complete extractor
result contains 15 uniquely mapped text hunks and no unmatched hunk. The
corresponding `zimbra-common-core-jar` package pair changes five JARs,
including `zimbrastore.jar`; that is evidence for the mailbox fixes, but is
not eligible for a text-hunk source extractor.

## Extractor scope

[`zm-web-client.json`](../../source-extractors/zm-web-client.json) maps the
three direct `.jsp`/`.tag` artifacts above and the specifically scoped
`Mail_all.js` bundle used by later release mappings.  It deliberately makes no
claims about JAR contents. Reproduce the package-backed result against the
historical releases with the Ubuntu 18 installer package source enabled:

```sh
scripts/ubuntu24-debian-non-patch-packages-pseudo-code-analysis source-extract \
  --ubuntu-series 18 --local-release 10.1.0 \
  zm-web-client 10.1.0 10.1.1
```

The result is written below
`results/ubuntu18/source-extractions/zm-web-client/10.1.0__to__10.1.1/`.  It
will either reconstruct only uniquely located source hunks or preserve
unmatched hunks for review; it must not be treated as confirmation of the
unmapped fixes.

## Additional package-backed release-note extractor

[`zm-admin-console.json`](../../source-extractors/zm-admin-console.json)
maps the `Admin_all.js` Ajx bundle from `zimbra-mbox-admin-console-war` to the
public `Zimbra/zm-admin-console` source tree.  It is not evidence for the
unmapped security rows above.  It does, however, deterministically reconstruct
the implementation of the 10.1.1 **Hide Alias in GAL** release-note item: the
`ZaAccount`, `ZaAccountXFormView`, and `ZaNewAccountXWizard` changes add
`zimbraHideAliasesInGal` to the Admin Console.

The Ubuntu 18 package pair is `10.1.0.1715843304-1.u18` to
`10.1.1.1723652473-1.u18`.  Run it with:

```sh
scripts/ubuntu24-debian-non-patch-packages-pseudo-code-analysis source-extract \
  --ubuntu-series 18 --local-release 10.1.0 \
  zm-admin-console 10.1.0 10.1.1
```

The focused `Admin_all.js` artifact produces 13 uniquely mapped source hunks
across six source files.  Two ambiguous bundle hunks are retained in its
unmatched report rather than guessed; the 68 other changed package artifacts
are explicitly outside this extractor's artifact scope.

[`zm-admin-ajax.json`](../../source-extractors/zm-admin-ajax.json) separately
maps `Ajax_all.js` from that same Debian package to
`Zimbra/zm-admin-ajax`.  It reconstructs one source hunk in `AjxUtil.js`,
relaxing the email-domain label expression from a two-character minimum to a
one-character minimum.  This directly corresponds to the 10.1.1 Admin Web
Console fixed issue for addresses with a one-letter sub-domain.  The focused
artifact has one exact match and no unmatched hunk:

```sh
scripts/ubuntu24-debian-non-patch-packages-pseudo-code-analysis source-extract \
  --ubuntu-series 18 --local-release 10.1.0 \
  zm-admin-ajax 10.1.0 10.1.1
```
