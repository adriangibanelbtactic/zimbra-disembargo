# Zimbra 10.1.1 security source-extractor review

This review assesses the security fixes listed in the [10.1.1 release
announcement](https://wiki.zimbra.com/index.php?title=Zimbra_Releases/10.1.1#Security_Fixes)
for deterministic Ubuntu 24.04 source extractors.  An extractor is only added
when a changed, textual package artifact has a declared public upstream source
scope.  A public upstream diff alone is not enough: the extractor must be able
to reconstruct its output from a package hunk.

## Inputs and limitation

`zm-build-print-repos.pl` from
[`maldua/zimbra-tag-helper`](https://github.com/maldua/zimbra-tag-helper) was
run with `zm-build` at tag `10.1.1`, and again at its previous release tag
`10.1.0`.  The repo lists are identical: 53 Zimbra repositories.  Of those,
only these repositories expose both tags:

```text
java-html-sanitizer-release-20190610.1
zm-admin-ajax
zm-admin-console
zm-ajax
zm-core-utils
zm-mailbox
zm-web-client
zm-zcs-lib
```

The current Ubuntu 24.04 non-patch APT metadata does not retain builds whose
versions begin with `10.1.0.` or `10.1.1.`.  Furthermore, Ubuntu 24.04 was not
a 10.1.1 GA platform.  Ubuntu 18, 20, and 22 retain the `10.1.1`
`zimbra-mbox-webclient-war` build but do not retain its `10.1.0` counterpart.
The checked-in original 10.1.0 installer manifests make the missing before
package available as a verified, host-extracted local APT source.  Run the
extractor with `--ubuntu-series 18 --local-release 10.1.0` (or the matching
20/22 series) to compare it with the retained 10.1.1 package.

This was validated with the Ubuntu 18 original package
`10.1.0.1716285217-1.u18` and the retained Ubuntu 18 package
`10.1.1.1723653022-1.u18`: `zm-web-client` reconstructed all eight textual
package hunks with no unmatched or ambiguous hunk.  The three resulting source
files are `restHead.tag`, `launchNewWindow.jsp`, and `launchZCS.jsp`.  The
corresponding `zimbra-common-core-jar` package pair changes five JARs,
including `zimbrastore.jar`; that is evidence for the mailbox fixes, but is
not eligible for a text-hunk source extractor.

## Result per announced fix

| CVE | Announcement focus | Extractor result | Evidence / boundary |
| --- | --- | --- | --- |
| CVE-2024-45513 | Stored XSS in `contacts/print` | **Not created** | The `zm-web-client` contact changes between these tags are contact-view lifecycle changes, not a print-endpoint sanitisation change. No deterministic artifact/source mapping was established. |
| CVE-2024-45519 | Unauthenticated command execution in postjournal | **Not created** | `zm-mta` has `10.1.0` but no `10.1.1` public tag. The announced package is also a patch package, outside this non-patch extractor workflow. |
| CVE-2024-45518 | SSRF to internal services | **Not created** | `zm-mailbox` contains the relevant `ProxyServlet`/`NetUtil` hardening, but it is compiled Java in mailbox JAR artifacts. JARs are intentionally excluded from deterministic text-hunk reconstruction. |
| CVE-2024-45194 | XSS through email account configuration | **Not created** | No matching sanitisation change was established from the tag diff and available package evidence. |
| CVE-2024-45517 | XSS in `/h/rest` | **Created: `zm-web-client`** | `WebRoot/WEB-INF/tags/rest/restHead.tag` changes to cook the RSS target-item name. It is shipped as the same text `.tag` artifact in `zimbra-mbox-webclient-war`. |
| CVE-2024-45515 | Briefcase metadata `Content-Type` validation | **Not created** | No matching public tag diff or deterministic textual artifact mapping was established. |
| CVE-2024-45516 | Crafted HTML in Classic UI | **Not created** | `zm-mailbox` adds OWASP `alt`-attribute handler filtering, but the relevant implementation is Java in a JAR and cannot be handled by the current extractor. |
| TBD | Second crafted-HTML Classic UI entry | **Not created** | The announcement supplies neither a CVE nor a distinct implementation detail sufficient to establish a separate deterministic mapping. |
| CVE-2024-45511 | Briefcase OnlyOffice formatter XSS | **Not created** | No matching public tag diff or deterministic textual artifact mapping was established. |
| CVE-2024-45512 | Stored XSS through folder-share notifications | **Not created** | The tag contains share-module changes, but they address deletion/tab handling rather than notification output sanitisation. |

## Extractor scope

[`zm-web-client.json`](../../source-extractors/zm-web-client.json) maps only
the three direct `.jsp`/`.tag` artifacts above.  It deliberately does not make
claims about bundled JavaScript or JAR contents.  Reproduce the package-backed
result against the historical releases with the Ubuntu 18 installer package
source enabled:

```sh
scripts/ubuntu24-debian-non-patch-packages-pseudo-code-analysis source-extract \
  --ubuntu-series 18 --local-release 10.1.0 \
  zm-web-client 10.1.0 10.1.1
```

The result is written below
`results/ubuntu18/source-extractions/zm-web-client/10.1.0__to__10.1.1/`.  It
will either reconstruct only uniquely located source hunks or preserve
unmatched hunks for review; it must not be treated as confirmation of the
unmapped fixes.
