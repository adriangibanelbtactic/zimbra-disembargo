# Zimbra 10.1.6 to 10.1.7 source-extractor review

## Announcement security-fix boundary

The [10.1.7 release announcement](https://wiki.zimbra.com/wiki/Zimbra_Releases/10.1.7)
(April 18, 2025) has no **Security Fixes** section and no security-fix table
entries.  Therefore there are **no announced security fixes to classify as
created/extended or not created** for this release.  Its Licensing and other
Fixed Issues are not treated as security fixes merely from their descriptions.

## Upstream-tag survey

Ran:

```sh
tools/release-security-extractor-review/survey-zimbra-upstream-tags 10.1.6 10.1.7
```

The survey reports that public `Zimbra/zm-build` has no `10.1.7` tag, so it
uses the preceding `10.1.6` `zm-build` configuration to select repositories.
Of its 53 selected repositories, these are the complete target-tag results
with a comparison baseline:

| Repository | `10.1.7` target tag | Survey baseline | Relevant public text change | Result |
| --- | --- | --- | --- | --- |
| `Zimbra/zm-core-utils` | present | `10.1.6` | `src/bin/zmlicensectl` (shell) | Not extended; the mapped `zimbra-core` package has no catalogued 10.1.7 build. |
| `Zimbra/zm-mailbox` | present | `10.1.6` | `store/conf/attrs/zimbra-attrs.xml`, plus Java source | Not created; the XML first appears in a new 10.1.7-only package and the remaining changed material is Java/JAR payload. |
| `Zimbra/zm-nginx-conf` | present | `10.1.0` | Nginx configuration templates | Not created; no corresponding 10.1.6/10.1.7 non-patch config-package pair is retained. |

The other 50 repositories selected by the target configuration have no public
`10.1.7` component tag, so the survey records no baseline for them and no
source comparison was inferred.  In particular, an absent `10.1.6` tag was
not used to reject a repository: `zm-nginx-conf` was compared with its recorded
`10.1.0` fallback.

The survey's `changes/` evidence is limited to the rows above: `zm-core-utils`
commits `ZCS-16412` and `ZCS-16604`; `zm-mailbox` changes the attributes XML
and Java sources; and `zm-nginx-conf` changes/adds configuration templates.
None is connected to an announcement Security Fixes entry, because there are
no such entries in this announcement.
