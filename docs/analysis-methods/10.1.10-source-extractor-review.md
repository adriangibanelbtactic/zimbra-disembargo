# Zimbra 10.1.10 source-extractor review

Reviewed 2026-10-16 for the `10.1.9` to `10.1.10` release umbrella. Debian
build IDs below identify package artifacts only; none is treated as an upstream
tag.

## Security-fix decisions

The [10.1.10 release announcement](https://wiki.zimbra.com/wiki/Zimbra_Releases/10.1.10#Security_Fixes)
lists five Security Fixes. All are **not created**; no extractor definition was
created or extended in this review.

| Security fix | Result | Evidence boundary |
| --- | --- | --- |
| GraphiQL disabled at `/modern/graphiql` | **Not created** | `zm-gql` is selected by the target `zm-build` configuration but has no public `10.1.10` tag in the survey, so it has no selected public source baseline. The `zimbra-modern-ui` package pair has changed payload artifacts, but no target-selected public repository/source scope from which to deterministically reconstruct this change. |
| `@babel/runtime` 7.27.6 ReDoS, CVE-2025-27789 | **Not created** | The target configuration provides no comparable public repository for the bundled Modern UI dependency. The `zimbra-modern-ui` package pair contains only 27 changed common artifacts, principally locale chunks (and many added hash-named bundles with no before side); this is not an explicit upstream source mapping or a uniquely matchable source hunk. |
| ResetPasswordRequest CSRF, CVE-2025-54390 | **Not created** | The comparable `Zimbra/zm-mailbox` survey records `4901e83f634d89e67cdbc74861de54c439be0465` (`ZBUG-4911`), which changes only `store/src/java/com/zimbra/soap/SoapEngine.java`. Java/JAR payloads are excluded by the extractor rules. |
| Auth token required for 2FA modifications, CVE-2025-54391 | **Not created** | The package-backed Classic client comparison has a uniquely matched `login.jsp` change, but it is the announced fixed issue `ZBUG-4772`: `onkeyup` became `oninput` for enabling the pasted-code Verify button. It does not enforce an auth token. The changed `TwoFactor_all.js` and `PasswordRecovery_all.js` hunks are the same unrelated `zm-ajax` Chrome/Safari namespace compatibility change, not a 2FA authorization check. No explicit public source scope and package hunk establish the announced auth-token change. |
| Rsync 3.4.1 upgrade | **Not created** | Ubuntu 18 package inspection compared `zimbra-rsync` `3.1.2-1zimbra8.7b1.18.04` to `3.4.1-1zimbra8.7b1.18.04`. The executable `opt/zimbra/common/bin/rsync` is a stripped ELF binary; the remaining common changes are rsync manual pages and a compressed Debian changelog. There is no target-selected Zimbra upstream source scope or qualifying installed source-text artifact. |

These boundaries intentionally do not infer a source path from a CVE or from a
package name.

## Package comparisons and extractor runs

The fixed-name analysis container was stopped before package work. Catalogue
availability was checked across Ubuntu 18, 20, 22, and 24; Ubuntu 18 retains
the release package pair used for extraction. Package launcher commands were
run sequentially:

```sh
scripts/ubuntu24-debian-non-patch-packages-pseudo-code-analysis start --ubuntu-series 18
scripts/ubuntu24-debian-non-patch-packages-pseudo-code-analysis catalog --ubuntu-series 18
scripts/ubuntu24-debian-non-patch-packages-pseudo-code-analysis source-extract --ubuntu-series 18 zm-web-client 10.1.9 10.1.10
scripts/ubuntu24-debian-non-patch-packages-pseudo-code-analysis source-extract --ubuntu-series 18 zm-ajax 10.1.9 10.1.10
```

Every extractor result has `comparison_role: release-baseline`; there are no
additional retained `10.1.10.*` package builds, so no immediate-predecessor
result was generated.

| Extractor | Package and exact pair | Public baseline | Role | Matched / unmatched | Result |
| --- | --- | --- | --- | --- | --- |
| `zm-web-client` (existing) | `zimbra-mbox-webclient-war`: `10.1.9.1749552817-1.u18` -> `10.1.10.1751290195-1.u18` | `10.1.9` | release-baseline | 2 / 0 | Existing mappings exactly reconstruct `WebRoot/public/login.jsp` and `WebRoot/js/zimbraMail/mail/controller/ZmMailConfirmController.js`. The former is the 2FA paste UI fixed issue; it is not the CVE-2025-54391 authorization change. |
| `zm-ajax` (existing) | `zimbra-mbox-webclient-war`: `10.1.9.1749552817-1.u18` -> `10.1.10.1751290195-1.u18` | `10.1.8` fallback | release-baseline | 3 / 0 | The unchanged extractor definition exactly reconstructs the three `AjxSoapDoc.js` namespace hunks from `Ajax_all.js`. The manifest records the requested `10.1.9` package label and `10.1.8` source fallback. |

The matched and unmatched reports and every manifest were inspected under:

```text
var/ubuntu24-debian-non-patch-packages-pseudo-code-analysis/results/ubuntu18/source-extractions/
```

For the web-client package pair, the two removed artifacts are versioned
`zm-ajax` and `zm-taglib` JARs; the two added artifacts are their replacement
JARs. They are not scoped text artifacts, so neither reconstructed diff has a
`deleted file mode` entry. The reports contain no unmatched text hunk and no
source deletion is intended. Added-only artifacts were not treated as
reconstructable.

Independent non-patch package inspections also established the security-fix
boundaries above:

| Package | Exact pair | Outcome |
| --- | --- | --- |
| `zimbra-modern-ui` | `4.45.0.1745923101-1.u18` -> `4.46.0.1751374774-1.u18` | 27 changed common artifacts plus added hash-named bundles; no selected public source repository or source scope for deterministic extraction. |
| `zimbra-rsync` | `3.1.2-1zimbra8.7b1.18.04` -> `3.4.1-1zimbra8.7b1.18.04` | Four common changes: stripped ELF `rsync`, two manual pages, and compressed changelog; two added rsync-ssl artifacts. No qualifying source artifact. |

No extractor definition changed: the two successful package-backed
reconstructions are already covered by the sole definitions for
`Zimbra/zm-web-client` and `Zimbra/zm-ajax`. Creating a definition for any
security row would either duplicate an existing upstream repository or lack an
explicit, uniquely matchable public source scope.
