# Zimbra 10.1.17 source-extractor review

Reviewed `10.1.16` → `10.1.17` with the Ubuntu 24 (Noble) Network Edition APT
repository. No definition was created or extended. The one qualifying installed
text change is already covered by the `zm-web-client` direct-root mapping; it
reconstructs both the changed REST tag and the removed REST tag exactly. The
other announced fixes have only JAR/class payload evidence, Java source, or no
explicit qualifying installed-text/source scope.

## Evidence sources

so no duplicate repository definition or scope extension was justified.

### Target-release upstream survey

Ran:

```sh
tools/release-security-extractor-review/survey-zimbra-upstream-tags \
  10.1.16 10.1.17
```

The requested `zm-build` tag `10.1.17` is unavailable, so the survey used the
preceding `zm-build` configuration tag `10.1.16` to select repositories. This
does not substitute an upstream component tag: `tag-status.tsv` then checks for
each selected component's `10.1.17` tag and records its baseline. Of 53 selected
repositories, these four have `10.1.17`, all with `10.1.16` as their recorded
baseline:

| Repository | Target / baseline | Review result |
| --- | --- | --- |
| `Zimbra/zm-admin-ajax` | `10.1.17` / `10.1.16` | `ZBUG-5302` is servlet Java; scoped `Ajax_all.js` did not change in the package. |
| `Zimbra/zm-ajax` | `10.1.17` / `10.1.16` | `ZBUG-5302` is servlet Java; scoped `Ajax_all.js` did not change in the package. |
| `Zimbra/zm-mailbox` | `10.1.17` / `10.1.16` | Delegated-send, attachment, LFI-related and quota commits are present; security scopes are Java or JAR-carried. |
| `Zimbra/zm-web-client` | `10.1.17` / `10.1.16` | `restDocument.tag` edit and `restDocumentView.tag` deletion are explicit, installed text changes. |

All remaining selected repositories lack a `10.1.17` component tag and were not
compared. The survey's logs and changed-path lists, not CVE wording, establish
the source scopes above.
