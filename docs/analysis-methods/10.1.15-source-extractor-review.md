# Zimbra 10.1.15 source-extractor review

Reviewed `10.1.14` → `10.1.15` on Ubuntu 18 (Bionic) against the public
Network Edition APT repository.  No extractor definition was created or
extended: the target release exposes its relevant change only as JAR payloads.

## Evidence sources

### Release announcement

The [10.1.15 release notes](https://wiki.zimbra.com/wiki/Zimbra_Releases/10.1.15)
and [release announcement](https://blog.zimbra.com/2025/11/patch-release-update-zimbra-10-1-15/)
describe a low-severity AntiSamy rendering optimization.  The release notes do
not have a separate **Security Fixes** table and publish no CVE.  Their sole
fixed issue refines CSS parser handling so safe non-standard CSS is not
unnecessarily sanitized while the AntiSamy protections remain in effect.

| Security fix | Result | Evidence boundary |
| --- | --- | --- |
| TBD — AntiSamy CSS parser/rendering optimization | **Not created** | The public `antisamy` change is explicit, but its implementation is Java and its shipped NE artifacts are `antisamy-1.7.8z.jar` files.  JAR/class/binary payloads and Java source are excluded; no changed common installed text artifact exists to uniquely reconstruct. |

### Target-release upstream survey

Ran:

```sh
tools/release-security-extractor-review/survey-zimbra-upstream-tags \
  10.1.14 10.1.15
```

The tool reported that `zm-build` has no `10.1.15` tag and used the preceding
`10.1.14` `zm-build` configuration to select 54 repositories.
`tag-status.tsv` is the full record: 53 selected repositories have no
`10.1.15` component tag and were not compared.  The only comparable repository
is below; its selected baseline follows the required lower-tag fallback rather
than treating the absent `10.1.14` component tag as a rejection.

| Repository | Target tag | Survey baseline | Relevant source scope |
| --- | --- | --- | --- |
| `Zimbra/antisamy` | `10.1.15` | `10.1.13` | `CssValidator`, `CssParser`, and related CSS/AntiSamy implementation changes are Java; the remaining related changes are build/dependency metadata and AntiSamy resource XML. |

The survey's `ZBUG-5223` commits explicitly corroborate the announcement's
CSS-parser focus.  They do not establish an installed text artifact or justify
inferring a package source mapping.

### Ubuntu non-patch package evidence and extractor execution

`catalog-availability` queried Ubuntu 18, 20, 22, and 24.  Ubuntu 18, 20, and
22 retain the target builds; Ubuntu 18 was selected because it retains both
listed target packages and the needed predecessor builds.  Packages were
downloaded and extracted only, never installed.

| Package comparison | Role | Findings |
| --- | --- | --- |
| `zimbra-common-core-libs` `10.1.14.1762779814-1.u18` → `10.1.15.1762779814-1.u18` | Direct package inspection; immediate catalogued predecessor | 129 changed common regular files: 128 JARs, including `opt/zimbra/lib/jars/antisamy-1.7.8z.jar`, and `changelog.Debian.gz`.  No changed common text artifact; no added or removed regular file. |
| `zimbra-mbox-store-libs` `10.1.13.1761912748-1.u18` → `10.1.15.1762779814-1.u18` | Direct package inspection; nearest retained predecessor because no `10.1.14.*` build is catalogued | 99 changed common regular files: 98 JARs, including `opt/zimbra/jetty_base/webapps/service/WEB-INF/lib/antisamy-1.7.8z.jar`, and `changelog.Debian.gz`.  No changed common text artifact; no added or removed regular file. |

There is no qualifying extractor candidate, so no extractor can produce a
package-backed `release-baseline` or `immediate-predecessor` result.  An actual
extractor invocation was nevertheless made with the requested unchanged
release labels:

```sh
scripts/ubuntu24-debian-non-patch-packages-pseudo-code-analysis \
  source-extract --ubuntu-series 18 zm-core-utils 10.1.14 10.1.15
```

It reported the public `zm-core-utils` baseline fallback `10.1.14` → `10.1.10`,
then correctly stopped because no catalogued mapped `zimbra-core` package build
begins with `10.1.15`.  It therefore produced no inspection directory,
`manifest.json`, matched/unmatched-hunk report, or `upstream.diff` to inspect.
The actual relevant package inspections above likewise cannot be passed to an
extractor without inventing a JAR mapping prohibited by the extractor rules.

## Deliverable

No `source-extractors/*.json` definition changed.  The package comparisons
also establish that there are no removed installed text artifacts requiring a
source deletion reconstruction; all common payload paths remain present and
the changed relevant artifacts are JARs.  Generated survey, package, and
extractor-attempt outputs remain under ignored `cache/` and `var/` paths.
