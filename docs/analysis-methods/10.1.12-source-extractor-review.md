# 10.1.12 source-extractor review

Reviewed `10.1.11` → `10.1.12` on 2026-10-16.  This release has no
package-backed source extractor candidate, so no extractor definition was
created or extended.

## Evidence sources

### Release announcement

The [10.1.12 release announcement](https://wiki.zimbra.com/wiki/Zimbra_Releases/10.1.12)
lists one Security Fixes entry and lists only one release package:
`zimbra-proxy-patch` version `10.1.12.1760086549-1`.

| Security fix | Result | Evidence boundary |
| --- | --- | --- |
| CVE-2025-62763 — SSRF in the chat proxy configuration | **Not created** | The announced package is `zimbra-proxy-patch`.  The required Debian comparison catalogue deliberately excludes every package whose name ends in `-patch`, so it cannot establish a changed *non-patch* installed artifact or an exact before/after package pair.  The public upstream change alone is insufficient for package-backed extraction. |

### Target-release upstream survey

Ran:

```sh
tools/release-security-extractor-review/survey-zimbra-upstream-tags \
  10.1.11 10.1.12
```

The survey reported that `zm-build` tag `10.1.12` was unavailable and used
the preceding `zm-build` tag `10.1.10` to obtain the target repository list.
`tag-status.tsv` contains 53 selected repositories: 51 have no component
`10.1.12` tag and therefore have no comparable source baseline.  The two
repositories with the target tag and their survey-selected public baselines
are:

| Repository | Has `10.1.12` | Baseline from `tag-status.tsv` | Relevant result |
| --- | --- | --- | --- |
| `Zimbra/zm-admin-ajax` | yes | `10.1.10` | Changes are Java source (`Props2JsServlet.java`, `RestFilter.java`, and `SkinResources.java`), not the announced chat-proxy fix; Java is outside extractor scope. |
| `Zimbra/zm-nginx-conf` | yes | `10.1.10` | The security-fix commit `141debb1f0df12ddb67b6b545adcdc915eaed9a7` (`ZBUG-5128: added host check for Chat`) changes `conf/nginx/nginx.conf.chat.common.template`.  It is explicit text/configuration source, but has no qualifying non-patch package comparison. |

The requested component baseline `10.1.11` is absent in both comparable
repositories; `10.1.10` is the first lower tag recorded by the survey, not a
package build identifier.  The `zm-nginx-conf` upstream patch adds host checks
in the chat template, corroborating the announcement but not supplying the
required installed-package evidence.

### Ubuntu non-patch package evidence and extractor execution

After refreshing `catalog-availability`, the Ubuntu 18, 20, 22, and 24
non-patch catalogues contained no `zimbra-proxy-patch` entry (by design).
For the actual extractor attempt, the Ubuntu 18
`zimbra-mbox-admin-console-war` builds jump from `10.1.10.1751279184-1.u18` to
`10.1.13.1759852961-1.u18`; there is no `10.1.11` or `10.1.12` pair.

An actual extractor invocation was attempted with the required unchanged
release labels:

```sh
scripts/ubuntu24-debian-non-patch-packages-pseudo-code-analysis \
  source-extract --ubuntu-series 18 zm-admin-ajax 10.1.11 10.1.12
```

It correctly selected upstream baseline `10.1.10` after reporting that
`zm-admin-ajax` lacks `10.1.11`, then stopped because no catalogued
`zimbra-mbox-admin-console-war` build begins with `10.1.12`.  Therefore it
created no inspection, `manifest.json`, `matched-artifact-hunks.json`,
`unmatched-artifact-hunks.json`, or `upstream.diff` to inspect.

There are no exact non-patch Debian before/after build pairs and no
`release-baseline` or `immediate-predecessor` comparison roles for this review.
The only announced build is the excluded patch-package build above; it is not
represented as a package-backed comparison.

## Extractor decision

No `source-extractors/*.json` file changed.  Creating a `zm-nginx-conf`
definition would be unsupported: although its upstream source path and text
change are explicit, no qualifying changed common artifact from a non-patch
Debian package is available to uniquely match against the selected `10.1.10`
baseline.  No removed installed artifacts were evidenced by a qualifying
package comparison, either.
