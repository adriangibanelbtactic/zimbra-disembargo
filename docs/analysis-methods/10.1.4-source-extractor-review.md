# Zimbra 10.1.3 to 10.1.4 source-extractor review

This review combines the [10.1.4 release announcement](https://wiki.zimbra.com/wiki/Zimbra_Releases/10.1.4#Security_Fixes), the `zm-build` component selection at `10.1.4`, and retained Ubuntu Network Edition Debian packages. An extractor is retained only when a scoped installed text artifact has a uniquely exact before-side match in its recorded public baseline. Java source, JAR/class payloads, and translated `ZaMsg*properties` / `ZsMsg*properties` are excluded.

## Target-tag survey and baselines

`survey-zimbra-upstream-tags 10.1.3 10.1.4` selected 53 repositories from the target `zm-build` configuration. Of those, the following ten have the `10.1.4` component tag and a lower baseline. The baseline is the first available lower tag in that repository, not a guessed uniform tag; a missing `10.1.3` component tag is not a rejection.

| Repository | Target tag | Recorded baseline | Relevant material or boundary |
| --- | --- | --- | --- |
| `antisamy` | `10.1.4` | `10.1.0` | `AntiSamyDOMScanner.java`; Java only. |
| `zm-admin-console` | `10.1.4` | `10.1.2` | Change-password JavaScript plus excluded `ZaMsg*properties`. |
| `zm-ajax` | `10.1.4` | `10.1.3` | `AjxStringUtil.js`. |
| `zm-core-utils` | `10.1.4` | `10.1.3` | `src/bin/zmlicensectl`; installed artifact is unchanged. |
| `zm-gql` | `10.1.4` | `10.1.2` | GraphQL servlet/authentication Java. |
| `zm-mailbox` | `10.1.4` | `10.1.3` | Feed, SOAP, HTML-sanitizer, and ChangePassword Java. |
| `zm-taglib` | `10.1.4` | `10.1.0` | Change-password Java and `META-INF/zm.tld`. |
| `zm-timezones` | `10.1.4` | `10.1.0` | Time-zone data and translations; not a security-fix candidate. |

| `zm-zcs-lib` | `10.1.4` | `10.1.1` | AntiSamy package-builder metadata, not installed source. |

The survey logs identify `ZCS-16214` for AntiSamy, `ZCS-12859` for GraphQL CSRF, and the ChangePassword changes in `zm-mailbox`, `zm-taglib`, `zm-admin-console`, and `zm-web-client`. They do not turn Java-only or unshipped source changes into extractor candidates.

## Security-fix decisions

The announcement has seven Security Fixes rows. **Extended** means an existing one-per-repository definition has a valid, scoped package-backed reconstruction; it does not mean a new definition was created.

| Security fix | Result | Evidence boundary |
| --- | --- | --- |
| Encoded `@import` statements in `<style>` tags (no CVE) | **extended** `zm-ajax` | The changed `Ajax_all.js` hunk uniquely maps to `zm-ajax` `WebRoot/js/ajax/util/AjxStringUtil.js` at `10.1.3` (1/1 exact matches; no unmatched hunks). The primary AntiSamy decoder implementation is Java and remains excluded. |
| CVE-2025-32354: GraphQL CSRF | **not created** | `zm-gql` changes only `GQLServlet.java` and `GQLAuthUtilities.java`. The package evidence is compiled JAR payload only; no shipped non-JAR text artifact supplies a deterministic source scope. |
| CVE-2025-25065: RSS-parser SSRF | **not created** | The relevant `zm-mailbox` change is Java (`FeedManager.java`), carried only in the changed common-core JAR package. No source path is inferred from the CVE description. |
| CVE-2025-25064: ZimbraSyncService SQL injection | **not created** | No selected upstream change provides a shipped text artifact for this endpoint. Related mailbox implementation is Java and the available package evidence is JAR-only. |
| CVE-2024-45516: Classic UI crafted-HTML XSS | **not created** | The sanitizer work is `zm-mailbox` Java (`HtmlDefang` and OWASP classes) in changed JARs. The separately reconstructed `ZmComposeView.js` hunk is `ZBUG-4484`, not this CVE. |
| CVE-2025-48700: Classic UI crafted-HTML XSS | **not created** | Same boundary as CVE-2024-45516: implementation evidence is Java/JAR payload, not an installed text source artifact. |
| ChangePassword API requires an auth token (no CVE) | **extended** `zm-web-client`, `zm-admin-console` | `h/changepass` uniquely maps to `zm-web-client` at `10.1.3` (1/1). The retained admin package fallback maps seven `Admin_all.js` hunks uniquely to `ZaController.js` and `ZaLoginDialog.js` at the survey-selected `10.1.2` baseline (7/7). Those hunks add/pass `authToken` and `csrfToken`; their associated Java and tag-library changes remain excluded. |

## Package-backed extraction runs

The package launcher was stopped before analysis, then started and catalogued sequentially for Ubuntu 18. Packages were downloaded and extracted for comparison; none were installed. The retained package builds are below. Each generated manifest was inspected, including exact Debian versions, `comparison_role`, and matched/unmatched reports.

| Extractor | Package pair | Role | Scoped artifact and reconstructed source | Report result |
| --- | --- | --- | --- | --- |
| [`zm-ajax`](../../source-extractors/zm-ajax.json) | `zimbra-mbox-webclient-war` `10.1.3.1728575700-1.u18` → `10.1.4.1732702939-1.u18` | `release-baseline` | `js/Ajax_all.js` → `WebRoot/js/ajax/util/AjxStringUtil.js` | 1 exact match; empty unmatched report. |
| [`zm-web-client`](../../source-extractors/zm-web-client.json) | `zimbra-mbox-webclient-war` `10.1.3.1728575700-1.u18` → `10.1.4.1732702939-1.u18` | `release-baseline` | `h/changepass`, `public/login.jsp`, and `js/Mail_all.js` → `WebRoot/h/changepass`, `WebRoot/public/login.jsp`, and `WebRoot/js/zimbraMail/mail/view/ZmComposeView.js` | 4 exact matches; empty unmatched report. |
| [`zm-admin-console`](../../source-extractors/zm-admin-console.json) | `zimbra-mbox-admin-console-war` `10.1.2.1725893697-1.u18` → `10.1.4.1732701960-1.u18` | `release-baseline` fallback | `js/Admin_all.js` → `WebRoot/js/zimbraAdmin/common/ZaController.js` (6) and `ZaLoginDialog.js` (1) | 7 exact matches; empty unmatched report. |

The first two commands used the requested labels `10.1.3 10.1.4`. The requested admin-console invocation also used those labels and selected the retained `10.1.2` package predecessor, but cannot read the nonexistent upstream `10.1.3` component tag. The explicit `10.1.2 10.1.4` fallback run uses the survey-recorded baseline and produces the package-backed result above; it is not a rejection based solely on the absent `10.1.3` tag.

There is one retained target build for each mapped package, so no `immediate-predecessor` comparison is distinct from these release-baseline comparisons. The web-client package has two removed and two added versioned JARs, and the admin-console package has two removed and two added versioned JARs. They are outside all three `artifact-positive` scopes. No scoped removed text artifact exists, and each reconstructed `upstream.diff` has no `deleted file mode` entry. Thus no source deletion is asserted.

No definition file needed amendment: the existing `artifact-positive` scopes, bundle derivations, and source roots already describe all three valid installed text artifacts. No duplicate definition was created.
