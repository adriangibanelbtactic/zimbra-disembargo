# Zimbra 10.1.3 to 10.1.4 source-extractor review

This review records the text-only source candidates found by comparing the
public Zimbra repository tags `10.1.3` and `10.1.4`, then validating their
installed-package artifacts with the Ubuntu 18 Zimbra repository.  An
extractor is added only when a changed installed text artifact has one or more
unique exact before-side matches in its public baseline source tree.

## Repository survey boundary

`zm-build` does not expose tag `10.1.3`; the repository-selection helper falls
back to the preceding build tag (`10.1.1`) for that side.  This does not alter
the source comparison: every changed repository below has both its own
`10.1.3` and `10.1.4` tags.

Of the selected repositories, four have both tags and changed paths:

| Repository | Changed source material | Result |
| --- | --- | --- |
| `zm-web-client` | `changepass`, `login.jsp`, and `ZmComposeView.js` | Added mappings to its extractor below. |
| `zm-ajax` | `AjxStringUtil.js` | Added a mapping to its extractor below. |
| `zm-core-utils` | `src/bin/zmlicensectl` | Not created: the matching `zimbra-license-tools` package pair changes a JAR, not the script. |
| `zm-mailbox` | Java only | Not created: Java implementation is supplied through changed JARs. |

Repositories which publish only one of the two tags are not evidence that a
source change did not occur and are deliberately not treated as candidates.

## Validated extractors

The package-backed validations use Ubuntu 18 package builds
`zimbra-mbox-webclient-war` `10.1.3.1728575700-1.u18` and
`10.1.4.1732702939-1.u18`.

| Extractor | Scoped installed artifact(s) | Reconstructed source | Exact hunks |
| --- | --- | --- | --- |
| [`zm-web-client`](../../source-extractors/zm-web-client.json) | `h/changepass`, `public/login.jsp`, `js/Mail_all.js` | `WebRoot/h/changepass`, `WebRoot/public/login.jsp`, `WebRoot/js/zimbraMail/mail/view/ZmComposeView.js` | 4 / 4 |
| [`zm-ajax`](../../source-extractors/zm-ajax.json) | `js/Ajax_all.js` | `WebRoot/js/ajax/util/AjxStringUtil.js` | 1 / 1 |

Run any one explicitly with its release pair:

```sh
scripts/ubuntu24-debian-non-patch-packages-pseudo-code-analysis source-extract \
  --ubuntu-series 18 <extractor-name> 10.1.3 10.1.4
```

Each definition uses `artifact-positive` to exclude the other 10.1.4 package
changes from its scope.  This retains only hunk evidence relevant to the
specified upstream repository and prevents unrelated JAR, generated, or text
changes from being presented as source mappings.
