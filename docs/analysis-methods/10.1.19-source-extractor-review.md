# 10.1.19 source-extractor review

Reviewed `10.1.18` → `10.1.19` on 2026-10-16.  The existing
`zm-web-client` extractor was extended for the installed Classic Web Client
JavaScript fix.  No extractor definition was created, preserving one definition
per upstream GitHub repository.

## Evidence sources

### Release announcement

The [10.1.19 release announcement](https://wiki.zimbra.com/wiki/Zimbra_Releases/10.1.19)
has one Security Fixes entry:

| Security fix | Result | Evidence boundary |
| --- | --- | --- |
| TBD — stored XSS in the Classic Web Client: crafted email could execute script in a user's session | **Created/extended** | The survey explicitly identifies `Zimbra/zm-web-client` and `WebRoot/js/zimbraMail/share/model/ZmObjectManager.js`.  The retained non-patch `zimbra-mbox-webclient-war` comparison changes the corresponding installed text artifact.  Both before-side hunks uniquely and exactly match that public baseline source file. |

The announcement does not provide a CVE ID or a source path; the source scope in
the result above comes from the upstream survey and package artifact, not from
the announcement description.

### Target-release upstream survey

Ran:

```sh
tools/release-security-extractor-review/survey-zimbra-upstream-tags \
  10.1.18 10.1.19
```

The `zm-build` `10.1.19` tag is unavailable, so the tool used its preceding
`10.1.16` release configuration.  `tag-status.tsv` records 53 selected
repositories.  `zm-web-client` is the sole selected repository with a
`10.1.19` component tag; its recorded first lower-series baseline is
`10.1.17`.  The other 52 selected repositories have no target component tag
and were not compared.

`changes/zm-web-client/log.tsv` records ZBUG-5644, “Sanitize url strings in
received email to prevent stored xss,” and `names.tsv` records the explicit
source path:

```text
WebRoot/js/zimbraMail/share/model/ZmObjectManager.js
```

The requested `10.1.18` tag is absent in this component.  The package launcher
therefore retained the requested release labels but used the survey baseline
`10.1.17` for public-source matching, as recorded in the extraction manifest.

### Ubuntu non-patch package evidence and extractor run

`catalog-availability` queried Ubuntu 18, 20, 22, and 24.  Each retains the
`10.1.19.1783175257-1` target WAR but no `10.1.18` WAR.  No matching original
installer manifest exists for 10.1.18 (the checked-in local-release manifests
cover 10.1.0 only).  Ubuntu 18 was used for the package-backed extraction; the
launcher selected its nearest retained predecessor while preserving
`10.1.18__to__10.1.19` as the release-review umbrella.

| Extractor | Package pair | Role | Upstream baseline | Result |
| --- | --- | --- | --- | --- |
| `zm-web-client` | `zimbra-mbox-webclient-war` `10.1.17.1776247073-1.u18` → `10.1.19.1783175257-1.u18` | `release-baseline` | `10.1.17` fallback | The changed common text artifact `opt/zimbra/jetty_base/webapps/zimbra/js/zimbraMail/share/model/ZmObjectManager.js` produced two exact, unique matches and no unmatched scoped hunks. |

There is one retained target build for the mapped Ubuntu 18 package, so no
`immediate-predecessor` result was generated.  The final `manifest.json`
records the exact versions, requested releases, fallback baseline, and
`release-baseline` role.  Its `upstream.diff` changes only
`WebRoot/js/zimbraMail/share/model/ZmObjectManager.js`, passing `true` to both
affected `findObjects` calls.

The comparison also detected two removed package artifacts, both JARs
(`zm-ajax-10.1.17.1771250079.jar` and `zm-taglib-10.1.17.1762506875.jar`), so
they are excluded binary payloads rather than removed text candidates.  Added
only artifacts have no before-side text and were not reconstructed.

## Extractor definition extended

- `source-extractors/zm-web-client.json` now scopes the direct installed
  `ZmObjectManager.js` artifact and maps it to JavaScript candidates under
  `WebRoot/js/zimbraMail/share/model`.

The package run matched two exact before-side hunks at source lines 448–454 and
567–573.  `matched-artifact-hunks.json` contains both matches;
`unmatched-artifact-hunks.json` is empty.  Generated survey data, packages, and
extraction results remain under ignored `cache/` and `var/` paths.
