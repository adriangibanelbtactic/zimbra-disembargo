# Zimbra 10.1.18 source-extractor review

Reviewed `10.1.17` → `10.1.18` using the Ubuntu 18 (Bionic) Network Edition
APT repository. No extractor definition was created or extended: the only
announced security-fix package evidence changes an nginx executable, not an
installed text artifact.

## Evidence sources

### Release announcement

The [10.1.18 release notes](https://wiki.zimbra.com/wiki/Zimbra_Releases/10.1.18)
has one Security Fixes-table entry under the `10.1.18` update heading. The later
`10.1.17` Security Fixes heading on that page is historical release-note content,
not an additional target-release security fix.

| Security fix | Result | Evidence boundary |
| --- | --- | --- |
| CVE-2026-49975 — denial of service through malicious HTTP requests | **Not created** | The announcement identifies the shipped `zimbra-nginx` build as `1.24.0-1zimbra8.8b7`. The Ubuntu 18 non-patch pair changes `opt/zimbra/common/sbin/nginx` (an executable) and `usr/share/doc/zimbra-nginx/changelog.Debian.gz` (compressed package metadata). There is no changed common installed text artifact, so there is no eligible before-side text hunk or explicit source mapping for a deterministic extractor. |

### Target-release upstream survey

Ran:

```sh
tools/release-security-extractor-review/survey-zimbra-upstream-tags \
  10.1.17 10.1.18
```

The requested `zm-build` tag `10.1.18` is unavailable, so the survey selected
repositories from preceding `zm-build` tag `10.1.16`. This does not replace a
component tag. `tag-status.tsv` checks each selected repository for `10.1.18`
and records that repository's own fallback baseline.

Of 53 selected repositories, only `Zimbra/zm-mailbox` has target tag `10.1.18`;
its recorded baseline is `10.1.17`. Its only change is
`8e40abe4dc97fe5847bd7dab8db7c61511fa0497`, `ZCS-19387: License Feature Usage
Count Mismatch After Upgrade to 10.1.17`, changing
`store/src/java/com/zimbra/cs/ldap/unboundid/UBIDLdapFilterFactory.java`. This
is Java licensing work, not the announced nginx security scope, and Java source
is excluded. Every other selected repository lacks `10.1.18` and was not
compared. In particular, the survey supplies no target-tagged public source
repository/scope for the nginx executable.

### Ubuntu non-patch packages and extractor run

The fixed-name analysis container was stopped before package analysis. Ubuntu
18 was then started and catalogued; package payloads were downloaded and
extracted only, never installed.

| Exact package pair | Comparison role | Findings |
| --- | --- | --- |
| `zimbra-nginx` `1.24.0-1zimbra8.8b6.18.04` → `1.24.0-1zimbra8.8b7.18.04` | `deb-inspect` immediate catalogued predecessor | Two changed common files, no additions or removals: the nginx executable and `changelog.Debian.gz`. The target build is the `b7` nginx build listed in the announcement. Neither is an installed source-text candidate. |

The requested-label extractor command was run exactly as a release review
requires:

```sh
scripts/ubuntu24-debian-non-patch-packages-pseudo-code-analysis source-extract \
  --ubuntu-series 18 zm-web-client 10.1.17 10.1.18
```

It reported that no catalogued `zimbra-mbox-webclient-war` build begins with
`10.1.18`. Therefore it created no package pair, `manifest.json`,
`matched-artifact-hunks.json`, or `unmatched-artifact-hunks.json`; no extractor
comparison role or matched/unmatched count can be claimed. Creating a temporary
nginx extractor merely to run this command would not satisfy the text-artifact,
explicit-upstream-scope, or exact-before-hunk requirements.

## Deliverable

No `source-extractors/*.json` file changed. The rejection is package-backed,
not inferred from the CVE: the retained NE nginx package confirms the changed
security build but contains only a binary implementation change and compressed
package metadata. Generated survey and package-analysis outputs remain under
ignored `cache/` and `var/` paths.
