# Zimbra 10.1.9 source-extractor review

Reviewed 2026-10-16 for the `10.1.8` to `10.1.9` release umbrella.  This
review does not treat Debian build IDs as upstream tags.

## Evidence and upstream tags

The [10.1.9 release announcement](https://wiki.zimbra.com/wiki/Zimbra_Releases/10.1.9#Security_Fixes)
lists two Security Fixes:

| Security fix | Result | Evidence boundary |
| --- | --- | --- |
| CVE-2025-53645: Admin Console denial of service | **Not created** | The announced Admin Console fix corresponds to `Zimbra/zm-admin-ajax` commit `15c341b975f5ac11191953883f118fe7e0ef39d7` (`ZBUG-4944`). Its changed public files are Java (`src/com/zimbra/kabuki/servlets/Props2JsServlet.java` and `src/com/zimbra/webClient/servlet/SkinResources.java`). The installed package comparison has no changed scoped text hunk; it replaces a `zm-admin-ajax` JAR. Java/JAR payloads are outside extractor scope. |
| CVE-2025-27915: stored XSS in the Classic Web Client | **Extended** `zm-web-client` | The announcement describes strengthened input sanitization. `Zimbra/zm-web-client` commit `19d1fdcc3ddf1d8f586faf119525aa1f6279f4ee` (`10.1.9 ZBUG-4927: Sanitize data before adding in DOM`) changes four installed JS files. Each of the five package hunks matched a single exact before-side location in the public `10.1.8` baseline; see [Package extraction](#package-extraction). |

`tools/release-security-extractor-review/survey-zimbra-upstream-tags 10.1.8 10.1.9`
was run.  `zm-build` has no `10.1.9` tag, so the survey used its preceding
`10.1.6` release configuration.  Its `tag-status.tsv` records:

| Repository | Has `10.1.9` | Survey baseline | Result |
| --- | --- | --- | --- |
| `Zimbra/zm-admin-ajax` | yes | `10.1.1` | Comparable; `10.1.8` is absent, so this is the required same-series fallback. |
| `Zimbra/zm-web-client` | yes | `10.1.8` | Comparable. |
| All other repositories selected by that configuration | no | none | Not comparable for this target release; no missing `10.1.8` tag was treated as a rejection. |

The survey `changes/*/log.tsv` and `names.tsv` were reviewed for both
comparable repositories.  The Admin Console source change is Java-only.  The
web-client source paths are:

- `WebRoot/js/zimbraMail/calendar/view/ZmQuickReminderDialog.js`
- `WebRoot/js/zimbraMail/calendar/view/ZmReminderDialog.js`
- `WebRoot/js/zimbraMail/mail/view/ZmInviteMsgView.js`
- `WebRoot/js/zimbraMail/voicemail/view/ZmCallListView.js`

## Package extraction

The fixed-name package-analysis container was stopped before package work.
Ubuntu 22 was selected because its retained `1010-ne` catalogue contains both
release builds.  The package launcher was run sequentially with:

```sh
scripts/ubuntu24-debian-non-patch-packages-pseudo-code-analysis start --ubuntu-series 22
scripts/ubuntu24-debian-non-patch-packages-pseudo-code-analysis catalog --ubuntu-series 22
scripts/ubuntu24-debian-non-patch-packages-pseudo-code-analysis source-extract --ubuntu-series 22 zm-admin-ajax 10.1.8 10.1.9
scripts/ubuntu24-debian-non-patch-packages-pseudo-code-analysis source-extract --ubuntu-series 22 zm-web-client 10.1.8 10.1.9
```

All produced manifests have `comparison_role: release-baseline`; there are no
additional retained `10.1.9.*` builds and therefore no immediate-predecessor
comparison.

| Extractor | Package | Exact package pair | Upstream baseline | Role | Result |
| --- | --- | --- | --- | --- | --- |
| `zm-admin-ajax` | `zimbra-mbox-admin-console-war` | `10.1.8.1745843325-1.u22` -> `10.1.9.1745843325-1.u22` | `10.1.1` fallback | release-baseline | 22 common artifacts changed, but no scoped `Ajax_all.js` text hunk (`matched: 0`, `unmatched: 0`); empty `upstream.diff`. |
| `zm-web-client` | `zimbra-mbox-webclient-war` | `10.1.8.1745848554-1.u22` -> `10.1.9.1749552817-1.u22` | `10.1.8` | release-baseline | Four scoped changed JS artifacts, five text hunks, all matched uniquely (`matched: 5`, `unmatched: 0`). |

The web-client extraction reconstructs these source paths in `upstream.diff`:

- `WebRoot/js/zimbraMail/calendar/view/ZmQuickReminderDialog.js` (two hunks)
- `WebRoot/js/zimbraMail/calendar/view/ZmReminderDialog.js`
- `WebRoot/js/zimbraMail/mail/view/ZmInviteMsgView.js`
- `WebRoot/js/zimbraMail/voicemail/view/ZmCallListView.js`

`source-extractors/zm-web-client.json` was extended, rather than adding a
second definition for `Zimbra/zm-web-client`, with direct mappings for the
three newly scoped installed artifacts.  `ZmInviteMsgView.js` was already
mapped.  The post-extension extraction manifest and matched/unmatched reports
were inspected at:

```text
var/ubuntu24-debian-non-patch-packages-pseudo-code-analysis/results/ubuntu22/source-extractions/zm-web-client/10.1.8__to__10.1.9/zimbra-mbox-webclient-war/10.1.8.1745848554-1.u22__to__10.1.9.1749552817-1.u22-2/
```

Both package comparisons contain two removed and two added versioned JAR
artifacts, not removed scoped text artifacts.  No source deletion is intended;
accordingly neither reconstructed `upstream.diff` contains a `deleted file
mode` entry.  Added-only JARs have no before-side text and are not candidates
for reconstruction.  The Admin Console changed JAR and Java-source boundary,
and all unscoped package artifacts, are explicitly excluded rather than
inferred from the CVE descriptions.
