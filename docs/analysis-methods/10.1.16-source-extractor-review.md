# Zimbra 10.1.16 source-extractor review

Reviewed `10.1.15` → `10.1.16` using the Ubuntu 18 (Bionic) Network Edition
APT repository.  No definition was created or extended.  Existing
`zm-web-client` and `zm-admin-console` definitions already reconstruct the two
eligible installed-text security changes; every other announced security change
is limited to JAR/class payloads, Java source, or a file added after the public
source baseline.

## Evidence sources

### Release announcement

The [10.1.16 release notes](https://wiki.zimbra.com/wiki/Zimbra_Releases/10.1.16)
Security Fixes table contains the following seven entries.  “Not created” for
an already covered change means no definition change was needed; it is not a
claim that the security fix has no package-backed reconstruction.

| Security fix | Result | Evidence boundary |
| --- | --- | --- |
| n/a — mail rendering stability while retaining protections | **Not created** | The survey records AntiSamy CSS/import hardening in `Zimbra/antisamy`; `zimbra-common-core-libs` replaces `antisamy-1.7.8z.jar` with `antisamy-1.5.8z4.jar`.  The changed common payload is JARs plus `changelog.Debian.gz`, not installed source text. |
| CVE-2026-33368 — XSS in Zimbra webmail | **Not created** | The pertinent surveyed `zm-mailbox` sanitization change (`ZBUG-5144`, `DefangFactory.java` and `LC.java`) is Java.  The related `zimbra-common-core-jar` payload changes only JARs and a compressed changelog.  No path was inferred from the CVE. |
| CVE-2026-33369 — authenticated LDAP injection | **Not created** | `ZBUG-5313` explicitly changes `zm-mailbox` `FolderAction.java`; the installed carrier is `zimbra-common-core-jar` JAR payload, which is excluded. |
| n/a — restore Classic PDF attachment preview securely | **Not created** | `ZBUG-5357` explicitly modifies `Zimbra/zm-web-client` `WebRoot/public/pdfjs/web/viewer.jsp`.  The installed JSP is added in the release-baseline package comparisons; its later in-release modification is `10.1.16.1769165958-1.u18` → `10.1.16.1770139981-1.u18`, but that path does not exist at public baseline `10.1.14`.  It has no exact baseline before-side source match. |
| CVE-2026-33370 — stored Briefcase XSS | **Not created (already covered)** | `ZBUG-5318` explicitly changes `WebRoot/WEB-INF/tags/rest/restBriefcase.tag`.  The changed common package tag has one exact source match through the existing `zm-web-client` root mapping; the two later release-baseline results and their immediate predecessor result are matched with no unmatched hunks. |
| CVE-2026-33371 — authenticated EWS XXE | **Not created** | `ZBUG-5138` explicitly changes `zm-mailbox` `W3cDomUtil.java`.  `zimbra-mbox-ews-service` has only `zm-ews-common.jar`, `zm-ews-store.jar`, and a compressed changelog changed. |
| CVE-2026-33372 — CSRF token accepted from request body | **Not created (already covered)** | The surveyed `ZCS-18382` changes are explicit in the web components.  Existing mappings uniquely reconstruct the installed `h/changepass` source and the Admin bundle hunk in `ZaController.js`; no duplicate or extension is justified. |

### Ubuntu non-patch packages and extractor runs

`catalog-availability` queried Ubuntu 18, 20, 22, and 24.  Ubuntu 18 retains
the target builds, the needed older web/admin package builds, and the one exact
`10.1.15` library pair, so it was used.  Packages were downloaded and extracted
only, never installed.  The `10.1.15` web/admin package builds are not retained;
the wrapper therefore retained the requested release labels while selecting its
nearest catalogue predecessor and reporting the public source fallback.
