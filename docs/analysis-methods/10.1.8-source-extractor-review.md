# 10.1.8 source-extractor review

Reviewed 10.1.7 → 10.1.8 against the [10.1.8 release
announcement](https://wiki.zimbra.com/index.php?title=Zimbra_Releases/10.1.8&oldid=71118),
the `zm-build` repository survey, and Ubuntu 22 non-patch NE Debian payloads.
No source extractor was created or extended.

## Upstream-tag survey

Command:

```sh
tools/release-security-extractor-review/survey-zimbra-upstream-tags 10.1.7 10.1.8
```

The tool reported that `Zimbra/zm-build` has no `10.1.8` tag and used its
preceding `10.1.6` tag to obtain the release configuration.  Its generated
`tag-status.tsv` checked all 53 repositories selected by that configuration.
Only the following six had a `10.1.8` component tag; the other 47 did not and
were not compared.  Baselines are those recorded by the survey, rather than an
assumption that every component has a `10.1.7` tag.

| Repository | Has target tag | Survey baseline | Relevant target-tag result |
| --- | --- | --- | --- |
| `Zimbra/zm-admin-console` | yes | `10.1.6` | DSN admin UI and message resources; not a security-fix candidate. |
| `Zimbra/zm-ajax` | yes | `10.1.4` | `Props2JsServlet.java` and `SkinResources.java` changed for ZCS-17098. |
| `Zimbra/zm-certificate-manager-admin-zimlet` | yes | `10.1.0` | Certificate-upload UI change; not a security-fix candidate. |
| `Zimbra/zm-mailbox` | yes | `10.1.7` | ZCS-17098 changes include `common/.../localconfig/LC.java` and `store/.../UserServlet.java`. |
| `Zimbra/zm-web-client` | yes | `10.1.6` | Logout-notification JS change; not a security-fix candidate. |
| `Zimbra/zm-zimlets` | yes | `10.1.0` | Classic Chat contact-card change; not a security-fix candidate. |

The selected source changes relevant to the announced DoS row are Java source
in `zm-ajax` and `zm-mailbox`.  Java source and its JAR/class payload are
outside extractor scope.

## NE package and extraction evidence

All package commands used the Ubuntu 22 (`jammy`) repository catalogue.  The
following inspected pairs are exact APT builds, not upstream-tag names.

| Package | Exact before → after package build | Result |
| --- | --- | --- |
| `zimbra-common-core-jar` | `10.1.7.1743164318-1.u22` → `10.1.8.1746025108-1.u22` | Six changed common artifacts, all JARs (`zimbraclient`, `zimbrasoap`, `zimbracommon`, `zimbra-native`, and `zimbrastore` JARs plus the Debian changelog); no changed shipped source text. No removed artifact. |
| `zimbra-common-mbox-conf-attrs` | `10.1.7.1743164103-1.u22` → `10.1.8.1746025108-1.u22` | Three changed common artifacts and no removals. The changed `opt/zimbra/conf/attrs/zimbra-attrs.xml` adds the separate DSN attributes announced under “What's New”; it is not the DoS local-config attribute. |
| `zimbra-clamav` | `1.0.6-1zimbra8.8b4.22.04` → `1.0.8-1zimbra8.8b4.22.04` | 26 changed common artifacts and no removals: ClamAV executables plus upstream manual pages. This is a component-version package update, not a Zimbra selected-repository source mapping. |

The existing `zm-ajax` extractor was also run against the requested release
labels:

```sh
scripts/ubuntu24-debian-non-patch-packages-pseudo-code-analysis \
  source-extract --ubuntu-series 22 zm-ajax 10.1.7 10.1.8
```

Its sole retained result is a **release-baseline** comparison:

| Extractor/package | Requested releases | Actual package pair | Upstream baseline | Matched/unmatched text hunks |
| --- | --- | --- | --- | --- |
| `zm-ajax` / `zimbra-mbox-webclient-war` | `10.1.7` → `10.1.8` | `10.1.6.1738908936-1.u22` → `10.1.8.1745848554-1.u22` | `10.1.4` (fallback because `zm-ajax` has no `10.1.7` tag) | 0 / 0 |

`manifest.json` records `comparison_role: "release-baseline"`; no distinct
immediate-predecessor result was generated.  The scoped `Ajax_all.js` artifact
did not change, so both `matched-artifact-hunks.json` and
`unmatched-artifact-hunks.json` are empty and `upstream.diff` is empty.  The
webclient package did have 166 changed common artifacts, two removals, and two
additions, but all 170 were outside this extractor's explicit
`artifact-positive` scope.  This confirms that removed artifacts were observed
but that none supports a `zm-ajax` source deletion.

## Security-fix decisions

| Announcement security fix | Decision | Evidence boundary |
| --- | --- | --- |
| CVE-2025-53645 — DoS; added `ajax_uri_max_assets_requests_allowed` | **Not created** | The survey locates the related ZCS-17098 work only in `zm-ajax` and `zm-mailbox` Java files.  The matching 10.1.7 → 10.1.8 NE `zimbra-common-core-jar` package changes JAR payloads only.  The changed mailbox XML package artifact is explicitly the unrelated DSN feature.  The actual scoped `zm-ajax` extractor run has no text hunk to match.  Therefore there is no changed shipped text artifact with an explicit, uniquely matchable source scope. |
| CVE-2025-20128 and CVE-2024-20505 — ClamAV 1.0.8 update | **Not created** | The announcement identifies an external ClamAV package-version upgrade.  The selected `zm-build` survey has no target-tagged Zimbra repository giving an explicit ClamAV source scope.  The inspected package changes executables and manual pages, not a uniquely mapped Zimbra source artifact or security hunk.  No extractor may be inferred from the CVE description or manual-page text. |

No definition was changed: the evidence does not meet the requirement for a
changed common NE text artifact with an explicit source mapping and a unique
before-side source match.
