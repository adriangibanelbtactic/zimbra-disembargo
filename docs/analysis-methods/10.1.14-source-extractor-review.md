# Zimbra 10.1.14 source-extractor review

Reviewed `10.1.13` → `10.1.14` on Ubuntu 22 (Jammy) against the public
Network Edition APT repository.  This review adds or extends **no** extractor.

## Evidence sources

* [10.1.14 release announcement](https://blog.zimbra.com/2025/11/emergency-patch-release-zimbra-10-1-14/)
  and [release notes](https://wiki.zimbra.com/wiki/Zimbra_Releases/10.1.14):
  the announcement labels the release an emergency security patch.  Its fixed
  issues are the IMAP synchronization/message-display regression in 10.1.13
  (MINA rollback) and slow Zimbra-user switching (license-data caching).  It
  does not assign CVEs or publish a separate Security Fixes table.
* `tools/release-security-extractor-review/survey-zimbra-upstream-tags 10.1.13 10.1.14`:
  `zm-build-print-repos.pl` selected 54 repositories at the target `zm-build`
  configuration.  Only `Zimbra/zm-mailbox`, `Zimbra/zm-web-client`, and
  `Zimbra/zm-zcs-lib` have `10.1.14`; each has `10.1.13` as the selected
  public baseline (no fallback).  The other 51 selected repositories have no
  `10.1.14` component tag, so have no comparable target source scope.
* Ubuntu 22 non-patch Debian payload comparisons and the extractor run listed
  below.  Packages were downloaded and extracted, never installed.

The existing `zm-web-client` extractor was run with:

```sh
scripts/ubuntu24-debian-non-patch-packages-pseudo-code-analysis source-extract \
  --ubuntu-series 22 zm-web-client 10.1.13 10.1.14
```

Its retained `release-baseline` manifest records the exact web-client build
pair above and baseline `10.1.13`; its normal configured scope produced zero
matched and zero unmatched text hunks.  A non-persistent candidate scope for
the directly installed `ZmSettings.js` was then run against the same package
pair.  Its one version-substitution hunk had zero matches and one unmatched
hunk (`no-baseline-before-side-match`): the installed before side contains
release-specific values, while the public `10.1.13` source has the
`@buildDateTime@`, `@buildRelease@`, and `@buildVersion@` placeholders.
`upstream.diff` was empty.  The temporary scope was removed; it is not an
extractor extension.

No immediate-predecessor result was generated: each reviewed package has one
retained `10.1.14.*` build and its selected `10.1.13.*` release baseline is
that package comparison.

| Security fix | Decision | Evidence boundary |
| --- | --- | --- |
