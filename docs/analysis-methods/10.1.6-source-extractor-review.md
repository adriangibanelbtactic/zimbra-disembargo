# Zimbra 10.1.5 to 10.1.6 source-extractor review

This review uses the 10.1.6 release announcement, the `zm-build` component
survey, and retained Ubuntu non-patch Debian packages. It accepts installed
text artifacts only; Java source, JAR/class payloads, and translation-only
`ZaMsg*properties` / `ZsMsg*properties` changes are outside extractor scope.

## Security-fix result

| CVE | Announcement focus | Result | Evidence boundary |
| --- | --- | --- | --- |
| None listed | Restrict write access to `/opt/zimbra/jetty/webapps` through `/opt/zimbra/bin/zmacl`; the announcement also identifies `zmfixperms` and service/patch-update reapplication. | **Not created.** | The selected public components identify the implementation, but no retained non-patch Debian package provides a changed common text artifact for it. `zimbra-core` is absent for 10.1.6 from the Ubuntu 18, 20, and 22 catalogues, so `zm-core-utils` cannot form a package pair. The available Ubuntu 18 `zimbra-core-components` pair changes only `usr/share/doc/zimbra-core-components/changelog.Debian.gz`; the Ubuntu 22 core JAR pair changes five JARs and `changelog.Debian.gz`. Thus there is no package before-side script hunk to uniquely match, and the added `zmacl` script would in any case have no before-side hunk. |

The release announcement's Security Fixes table has this single, non-CVE row.
No extractor definition was created or extended.

## Ubuntu package and extractor evidence

The package launcher was stopped before analysis, then Ubuntu 18, 20, and 22
catalogues were refreshed sequentially. The following retained package evidence
was inspected:

| Ubuntu series | Package build pair | Evidence |
| --- | --- | --- |
| 18 | `zimbra-core-components` `10.1.5-1zimbra10.0b1.18.04` → `10.1.6-1zimbra10.0b1.18.04` | One changed common regular file: compressed `changelog.Debian.gz`; neither package ships the security scripts. |
| 22 | `zimbra-common-core-jar` `10.1.5.1737379628-1.u22` → `10.1.6.1738737738-1.u22` | Six changed common artifacts: `zimbra-native.jar`, `zimbraclient.jar`, `zimbracommon.jar`, `zimbrasoap.jar`, `zimbrastore.jar`, and compressed `changelog.Debian.gz`; none is an eligible text artifact. |
| 22 | `zimbra-mbox-webclient-war` `10.1.5.1737655177-1.u22` → `10.1.6.1738908936-1.u22` | The actual `zm-web-client` extractor run below found 177 changed common artifacts, two removed artifacts, and three added artifacts. |

`source-extract --ubuntu-series 18|20|22 zm-core-utils 10.1.5 10.1.6`
used the recorded `10.1.4` source fallback for `Zimbra/zm-core-utils`, then
correctly stopped because no catalogue has a `zimbra-core` build beginning with
`10.1.6`. It produced no extraction manifest or comparison role; this is an
unavailable package pair, not package-backed validation.

The successful package-backed extractor invocation was:

```text
source-extract --ubuntu-series 22 zm-web-client 10.1.5 10.1.6
```

It generated exactly one result for `zimbra-mbox-webclient-war`
`10.1.5.1737655177-1.u22` → `10.1.6.1738908936-1.u22`. Its manifest records
requested releases `10.1.5` / `10.1.6`, upstream baseline `10.1.5`, and
comparison role `release-baseline`; no immediate-predecessor result was needed.
Both `matched-artifact-hunks.json` and `unmatched-artifact-hunks.json` are
empty: all 179 changed or removed common artifacts were outside this
extractor's explicit artifact scope, and added-only artifacts cannot supply a
before-side hunk. The resulting `upstream.diff` is empty.

This successful run validates the existing extractor workflow only. It does not
provide package evidence for the announced write-access security fix.
