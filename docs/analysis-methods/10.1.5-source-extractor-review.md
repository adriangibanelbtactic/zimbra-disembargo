# Zimbra 10.1.4 to 10.1.5 source-extractor review

This review records the text-only public-source candidates selected by the
`zm-build` repository lists for `10.1.4` and `10.1.5`, then validates them
against the retained Ubuntu 18 package pair.  A source extractor is extended
only when an installed text artifact has a unique, exact before-side match in
its public baseline source scope.

## Repository survey boundary

`zm-build-print-repos.pl` selects the same 53 repositories at both release
labels.  Only two repositories publish both their own `10.1.4` and `10.1.5`
tags:

| Repository | Changed source material | Result |
| --- | --- | --- |
| `zm-web-client` | `ZmInviteMsgView.js` and `Message.template` | Added two mappings to the existing `zm-web-client` extractor. |
| `zm-mailbox` | `ZimbraAuthToken.java` and `RefreshRegisteredAuthTokens.java` | Not created: Java implementation is supplied in changed JAR artifacts. |

Repositories that expose only one tag cannot demonstrate the absence of a
source change and are not candidates for this comparison.

## Validated extractor extension

The Ubuntu 18 `zimbra-mbox-webclient-war` package pair is
`10.1.4.1732702939-1.u18` to `10.1.5.1737655177-1.u18`.
[`zm-web-client`](../../source-extractors/zm-web-client.json) maps these
source-faithful package artifacts:

| Installed artifact | Reconstructed source | Exact hunks |
| --- | --- | --- |
| `js/zimbraMail/mail/view/ZmInviteMsgView.js` | `WebRoot/js/zimbraMail/mail/view/ZmInviteMsgView.js` | 1 / 1 |
| `conf/templates/mail/Message.template` | `WebRoot/templates/mail/Message.template` | 1 / 1 |

Both changes are from `10.1.5 ZBUG-4677: Sanitize data before adding in DOM`.
The package also contains generated bundle/template output for these changes;
the extractor deliberately uses the direct text artifacts rather than infer
source from generated output.

Run the validation with:

```sh
scripts/ubuntu24-debian-non-patch-packages-pseudo-code-analysis source-extract \
  --ubuntu-series 18 zm-web-client 10.1.4 10.1.5
```
