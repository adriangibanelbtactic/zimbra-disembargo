# Zimbra 10.1.4 to 10.1.5 source-extractor review

This review records the text-only public-source candidates selected by the
`zm-build` `10.1.5` release configuration, then validates them against the
retained Ubuntu 18 non-patch Debian package builds.  An extractor is extended
only when an installed text artifact has a unique, exact before-side match in
its public baseline source scope.

The [10.1.5 release announcement](https://wiki.zimbra.com/wiki/Zimbra_Releases/10.1.5)
has one **Security Fixes** entry: CVE-2025-27915, a stored XSS issue in the
Classic Web Client.  The announcement lists `zimbra-mbox-webclient-war` and
`zimbra-common-core-jar` among the 10.1.5 packages.  `zimbra-patch` is outside
this review because the non-patch package catalogue deliberately excludes
packages whose names end in `-patch`.

## Repository survey boundary

`survey-zimbra-upstream-tags 10.1.4 10.1.5` invokes
`zm-build-print-repos.pl` at the target release and selects 53 repositories.
For each selected repository, `tag-status.tsv` checks for `10.1.5` and, only
when it exists, records the first lower available tag in the series.  Two
repositories have the target tag, each with `10.1.4` as its recorded baseline:

| Repository | Changed source material | Result |
| --- | --- | --- |
| `zm-web-client` | `ZmInviteMsgView.js` and `Message.template` | Extended the existing `zm-web-client` extractor with two direct-text mappings. |
| `zm-mailbox` | `ZimbraAuthToken.java` and `RefreshRegisteredAuthTokens.java` | Not created: Java implementation; the installed counterpart changes are JAR artifacts. |

The other 51 target-selected repositories have no `10.1.5` tag, so there is no
public target-tag comparison or fallback baseline for them.  Their absence is
not evidence that they did not change; they are not candidates for this source
comparison.  No selected repository needed a lower-than-`10.1.4` fallback.

`changes/zm-web-client/log.tsv` identifies the source change as `10.1.5
ZBUG-4677: Sanitize data before adding in DOM`, consistent with the
announcement's input-sanitization boundary.  The `zm-mailbox` log instead
contains two reverts for ZBUG-3250; it is recorded only as a target-tag source
comparison, not inferred to implement the CVE.

## Validated extractor extension

The Ubuntu 18 `zimbra-mbox-webclient-war` release-baseline package pair is
`10.1.4.1732702939-1.u18` to `10.1.5.1737655177-1.u18`.
[`zm-web-client`](../../source-extractors/zm-web-client.json) was extended with
these source-faithful package artifacts:

| Installed artifact | Reconstructed source | Exact hunks |
| --- | --- | --- |
| `js/zimbraMail/mail/view/ZmInviteMsgView.js` | `WebRoot/js/zimbraMail/mail/view/ZmInviteMsgView.js` | 1 / 1 |
| `conf/templates/mail/Message.template` | `WebRoot/templates/mail/Message.template` | 1 / 1 |

Both package hunks had exactly one `exact-baseline-before-side` match at public
baseline `10.1.4` (`14000d57e2eb24180a262f7324210739c324cdab`).  The extractor
run generated one manifest, with requested releases `10.1.4`/`10.1.5`, exact
versions above, and `comparison_role: release-baseline`; there was no separate
immediate-predecessor result.  Its reports contain two matched hunks and zero
unmatched hunks.  The package has two removed and two added artifacts, but all
four are versioned JAR names (`zm-ajax` and `zm-taglib`), not removed text
artifacts.  The extractor deliberately scopes its mapping with
`artifact-positive` to the two direct text artifacts rather than inferring
source from generated bundle output.

For the other announced package, the Ubuntu 18
`zimbra-common-core-jar` package pair is
`10.1.4.1733200444-1.u18` to `10.1.5.1737379628-1.u18`.  All six changed common
files are five JARs plus the package changelog; there are no removed or added
files.  This supports the rejection of the `zm-mailbox` Java changes and does
not justify a text source extractor.

## Security-fix outcome

| Security fix | Result | Evidence boundary |
| --- | --- | --- |
| CVE-2025-27915: stored XSS in the Classic Web Client | **Extended** `zm-web-client` | The announcement describes input sanitization; the target-tag survey identifies two changed web-client text files; the Ubuntu 18 non-patch package pair contains both installed text artifacts; and the extractor run uniquely matches both before-side hunks with no unmatched hunks. This reconstruction covers those mapped package hunks only, not an upstream-only CVE attribution. |

No extractor was created.  The only rejection is `zm-mailbox`: its two
target-tag changes are Java source and the installed `zimbra-common-core-jar`
comparison contains JAR payload changes, which are excluded by the extractor
rules.

Run the validation with:

```sh
scripts/ubuntu24-debian-non-patch-packages-pseudo-code-analysis source-extract \
  --ubuntu-series 18 zm-web-client 10.1.4 10.1.5
```
