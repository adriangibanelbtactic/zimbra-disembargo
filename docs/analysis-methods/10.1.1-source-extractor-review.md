# 10.1.1 source-extractor review

## Scope and evidence

This review covers the 4 September 2024 [10.1.1 release announcement](https://wiki.zimbra.com/wiki/Zimbra_Releases/10.1.1), specifically its 13 **Security Fixes** rows.  It uses the public release announcement, the target `zm-build` repository selection, and a non-patch Ubuntu Debian payload comparison.  It does not attribute a source path from a CVE description alone.

The upstream survey was run as follows:

```sh
tools/release-security-extractor-review/survey-zimbra-upstream-tags 10.1.0 10.1.1
```

`cache/release-security-extractor-review/surveys/10.1.0__to__10.1.1/tag-status.tsv`
records the target configuration and the baseline actually selected for every repository.  The eight repositories with a `10.1.1` tag all selected `10.1.0` as their first available lower same-series baseline:

| Repository | Target tag | Baseline | Relevant survey result |
| --- | --- | --- | --- |
| `java-html-sanitizer-release-20190610.1` | yes | `10.1.0` | Java-only sanitizer changes |
| `zm-admin-ajax` | yes | `10.1.0` | forwarding-address change |
| `zm-admin-console` | yes | `10.1.0` | admin JavaScript and translations |
| `zm-ajax` | yes | `10.1.0` | random-string utility |
| `zm-core-utils` | yes | `10.1.0` | licensing and OnlyOffice scripts |
| `zm-mailbox` | yes | `10.1.0` | Java-only mailbox, sanitizer, and proxy changes |

| `zm-zcs-lib` | yes | `10.1.0` | package-builder change |

## Ubuntu package and extraction evidence

Ubuntu 24 APT metadata no longer provides the old pair.  The review therefore used the documented Ubuntu 22 local-release workflow: the verified `10.1.0_GA` Ubuntu 22 installer supplied the before package and the Zimbra `1010-ne` Jammy APT index supplied the after package.

The package launcher requires the command first.  The canonical review form
places `--ubuntu-series` and `--local-release` after that command and before
its positional arguments.  In particular, `deb-inspect` has no `--before`
option: `--after VERSION` compares that version with its immediate catalogued
predecessor.  The release-pair extraction used the explicit positional labels
shown below, rather than an invented `--before` switch.

| Item | Evidence |
| --- | --- |
| Package | `zimbra-mbox-webclient-war` |
| Before | `10.1.0.1721128572-1.u22`, SHA-256 `8f40b457a831516fdc9e6440a0eed69174a0ae0855a5df077f5efa88a9c5cdb6` |
| After | `10.1.1.1723653022-1.u22`, SHA-256 `3f9bd4040a8e711c5361d7285fd41411732dd9a45fa69c4dc5d3ebe14ea7c2d4` |
| Inspection | 268 changed common regular files, two removed files, and two added files; package payloads were extracted but never installed. |
| Relevant text | `WEB-INF/tags/rest/restHead.tag`, `public/launchNewWindow.jsp`, `public/launchZCS.jsp`, and `js/Mail_all.js` changed.  The translated `ZmMsg*properties` files were excluded. |

The package hunk in `restHead.tag` changes the REST link target to `zm:cook(...)`.  The hunk in `launchNewWindow.jsp` removes `request.getParameter("packages")`; related `packages` handling changed in `launchZCS.jsp`.  Those are explicit package-artifact and public-source connections, not CVE-derived path guesses.

The two removed artifacts were versioned `zm-ajax` and `zm-taglib` JARs, replaced by JARs with `10.1.1` names.  They are binary payloads, so no removed text artifact was eligible for a source deletion.  Accordingly, no deletion was intended and the reconstructed `upstream.diff` has no `deleted file mode` entry.

The following run used the selected public baseline and inspected both reports:

```sh
scripts/ubuntu24-debian-non-patch-packages-pseudo-code-analysis \
  source-extract --ubuntu-series 22 --local-release 10.1.0 \
  zm-web-client 10.1.0 10.1.1
```

It wrote `results/ubuntu22/source-extractions/zm-web-client/10.1.0__to__10.1.1-2/`.  `matched-artifact-hunks.json` records 15 exact, unique before-side matches and `unmatched-artifact-hunks.json` is empty.  `upstream.diff` includes the expected paths:

* `WebRoot/WEB-INF/tags/rest/restHead.tag`;
* `WebRoot/public/launchNewWindow.jsp` and `WebRoot/public/launchZCS.jsp`; and
* the uniquely matched source portions of `Mail_all.js`.

The existing `zm-web-client` definition already scopes these direct artifacts, its REST tag root, and the `Mail_all.js` bundle.  No definition change was needed, and no new definition may be created for its already-covered `Zimbra/zm-web-client` repository.

The release package list identifies `zimbra-patch`, `zimbra-mta-patch`, `zimbra-onlyoffice-patch`, and `zimbra-proxy-patch` as patch packages.  They are outside this non-patch extractor workflow.  As a control, the non-patch `zimbra-mta-components` `10.1.0` → `10.1.1` Ubuntu 22 comparison changed only `usr/share/doc/zimbra-mta-components/changelog.Debian.gz`, not `postjournal` or another source artifact.  The non-patch web-client TinyMCE payload files were also unchanged; an upstream TinyMCE upgrade in a patch package cannot be reconstructed here.

## Security-fix decisions

“Created/extended” below means that a deterministic extractor scope already exists and was package-backed validated in this review; it does not claim a new JSON definition where the existing definition already covers the same upstream repository and artifact.  “Not created” is an explicit evidence boundary.

| CVE | Announcement focus | Result | Evidence boundary |
| --- | --- | --- | --- |
| CVE-2024-45513 | Stored XSS at `contacts/print` | **Not created** | The comparable `zm-mailbox` changes are Java source, and no explicit matching non-patch installed text artifact/source scope was established.  Do not infer one from the endpoint name. |
| CVE-2024-45519 | Unauthenticated postjournal command execution | **Not created** | The release delivers `zimbra-mta-patch`, which is excluded.  The non-patch `zimbra-mta-components` comparison changed only its compressed Debian changelog; no changed text artifact was available. |
| CVE-2024-45518 | SSRF to internal services | **Not created** | The plausible comparable `zm-mailbox` proxy change is Java-only and would be shipped as compiled/JAR material; no changed non-patch text artifact was established. |
| CVE-2024-45194 | XSS through email account configurations | **Not created** | The web-client extraction has other matched Classic UI text, but no public commit/package hunk explicitly identifies this announced issue.  A source path was not inferred from the description. |
| CVE-2024-45517 | XSS at `/h/rest` | **Created/extended** | Existing `zm-web-client` REST-root mapping exactly and uniquely matched the changed installed `restHead.tag` before-side hunk to `WebRoot/WEB-INF/tags/rest/restHead.tag`; it is present in the generated `upstream.diff`. |
| CVE-2024-45515 | Briefcase import metadata Content-Type XSS | **Not created** | No explicit changed non-patch text artifact/source scope was established.  The relevant comparable mailbox work is Java-only or patch-delivered. |
| CVE-2024-45516 | Classic UI crafted-HTML XSS | **Not created** | Comparable sanitizer/mailbox changes are Java-only; the package-backed text run does not identify this specific fix. |
| CVE-2024-45514 | Non-sanitized `packages` parameter XSS | **Created/extended** | Existing `zm-web-client` mapping exactly and uniquely matched the installed `launchNewWindow.jsp` and `launchZCS.jsp` before-side hunks.  The former explicitly removes `request.getParameter("packages")`; both paths are in `upstream.diff`. |
| TBD | Classic UI crafted-HTML XSS | **Not created** | Duplicate generic announcement wording supplies no distinct explicit source scope; the same Java/JAR and attribution boundary as CVE-2024-45516 applies. |
| CVE-2024-45511 | OnlyOffice formatter reflected XSS | **Not created** | The announced delivery is `zimbra-onlyoffice-patch`; patch packages are excluded and no non-patch text artifact was identified. |
| CVE-2024-45512 | Briefcase share-notification stored XSS | **Not created** | No explicit changed non-patch text artifact/source scope was established; do not equate unrelated changed Briefcase JavaScript with this announced issue. |
| CVE-2024-45510 | Stored XSS adding contacts from crafted email | **Not created** | The plausible comparable `zm-mailbox` contact changes are Java-only, with no package-backed text artifact eligible for extraction. |
| CVE-2024-38356 | TinyMCE 7.1.1 → 7.2.0 XSS fix | **Not created** | The non-patch `zimbra-mbox-webclient-war` TinyMCE files did not change.  The announcement's patch-package delivery cannot establish a package-backed public-source extraction. |

## Extractor result

No `source-extractors/*.json` file was added or modified.  The one existing definition for `Zimbra/zm-web-client` is sufficient for the two explicit, package-backed text candidates, while every other security row fails at least one required condition above.
