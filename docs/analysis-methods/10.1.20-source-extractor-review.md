# 10.1.20 source-extractor review

## Scope and evidence

This review covers the `10.1.19` to `10.1.20` release umbrella.  The security
fix list is the [10.1.20 release announcement](https://blog.zimbra.com/2026/07/patch-release-update-zimbra-10-1-20/),
which deliberately supplies no CVE IDs or source paths.

`tools/release-security-extractor-review/survey-zimbra-upstream-tags 10.1.19
10.1.20` selected repositories through `zm-build-print-repos.pl` at the target
release.  Its ignored `tag-status.tsv` has target tags, and therefore eligible
source baselines, only for:

| Repository | Target tag | Survey baseline |
| --- | --- | --- |
| `Zimbra/zm-ajax` | `10.1.20` | `10.1.17` |
| `Zimbra/zm-mailbox` | `10.1.20` | `10.1.18` |
| `Zimbra/zm-web-client` | `10.1.20` | `10.1.19` |

Every other repository selected by the target `zm-build` configuration had no
`10.1.20` tag: `ant-1.7.0-ziputil-patched`, `antisamy`, `ant-tar-patched`,
`ical4j-0.9.16-patched`, `java-html-sanitizer-release-20190610.1`,
`nekohtml-1.9.13`, `zm-admin-ajax`, `zm-admin-console`,
`zm-admin-help-common`, `zm-amavis`, `zm-aspell`,
`zm-bulkprovision-admin-zimlet`, `zm-bulkprovision-store`,

`zm-certificate-manager-store`, `zm-charset`, `zm-clam-scanner-store`,
`zm-core-utils`, `zm-db-conf`, `zm-dnscache`, `zm-downloads`, `zm-freshclam`,
`zm-gql`, `zm-helptooltip-zimlet`, `zm-jetty-conf`, `zm-jython`,
`zm-launcher`, `zm-ldap-utilities`, `zm-ldap-utils-store`, `zm-licenses`,
`zm-migration-tools`, `zm-mta`, `zm-nginx-conf`, `zm-nginx-lookup-store`,
`zm-oauth-social`, `zm-openid-consumer-store`, `zm-pkg-tool`, `zm-postfix`,
`zm-proxy-config-admin-zimlet`, `zm-ssdb-ephemeral-store`, `zm-taglib`,

The comparable source changes establish these explicit scopes:

- `zm-ajax`: `WebRoot/js/ajax/dwt/widgets/DwtListView.js` (ZBUG-5499,
  stored XSS in an account-name field).
- `zm-web-client`: `WebRoot/js/zimbraMail/mail/model/ZmMailListFromGroup.js`
  (ZBUG-5583, sender-name sanitisation) and
  `WebRoot/js/zimbraMail/mail/view/ZmMailMsgView.js` (ZBUG-5608, attachment
  name sanitisation).
- `zm-mailbox`: the announced-looking forwarding, delegation, and XHTML
  attachment changes are Java source only.  They are not extractor candidates.

The web-client package comparison contained 176 changed common files, two
removed JARs (`zm-ajax-10.1.19.1771250079.jar` and
`zm-taglib-10.1.19.1762506875.jar`), and two replacement JARs.  The removed
artifacts are binary payloads, so no source deletion is applicable.  Within the
extractor scopes, the changed text hunks were:

- `Ajax_all.js` uniquely mapped to `zm-ajax`'s `DwtListView.js`.
- `ZmMailListFromGroup.js` uniquely mapped to its same-relative source path.
- `ZmMailMsgView.js` uniquely mapped to its same-relative source path.

The `zm-web-client` matched report has both direct artifacts and its unmatched
report is empty.  The `zm-ajax` matched report has the bundled `Ajax_all.js`
hunk and its unmatched report is empty.  The reconstructed diffs contain only
those exact before-side matches.

## Extractor decision

Extended the single existing definition for `Zimbra/zm-web-client`:

- Added the installed artifact
  `opt/zimbra/jetty_base/webapps/zimbra/js/zimbraMail/mail/model/ZmMailListFromGroup.js`.
- Mapped it in `zimbra-mbox-webclient-war` to
  `WebRoot/js/zimbraMail/mail/model` with the `.js` suffix.

The package hunk changes `fromParticipant.getText()` to
`AjxStringUtil.htmlEncode(fromParticipant.getText())`.  It had exactly one
before-side match at lines 63--69 of the public `10.1.19` baseline.  No new
definition was created: the repository already has `zm-web-client.json`.

## Announced security-fix decisions

| Announcement security fix | Decision | Evidence boundary |
| --- | --- | --- |
| SNMP command injection when notifications are enabled | Not created | The announcement supplies no source path.  No target-tagged comparable repository identifies an SNMP source scope, so none was inferred from the description. |
| Stored Classic Web Client XSS through attachment filenames | Not created (already covered) | `ZmMailMsgView.js` is already scoped by `zm-web-client`; the installed web-client pair and exact matched hunk encode `att.label`. |
| Classic Web Client XSS through crafted fields | Not created (already covered) | The existing `zm-ajax` `Ajax_all.js` bundle mapping exactly reconstructs the `DwtListView.js` encoding hunk, using the survey's `10.1.17` fallback baseline. |
| Classic Web Client XSS through a crafted field when rendered | **Extended `zm-web-client`** | The new `ZmMailListFromGroup.js` mapping has one exact package before-side match, and the run has no unmatched scoped hunk. |
| Classic Web Client XSS through crafted attachments when rendered | Not created | The corresponding `zm-mailbox` survey change is Java (`XHtmlDocumentHandler.java`); the changed non-patch mailbox payload is JARs, not installed text. |
| Mail-forwarding restriction bypass | Not created | The explicit `zm-mailbox` changes (`SoapToSieve.java` and `ZimbraMailAdapter.java`) are Java; the non-patch mailbox package comparison has no changed installed text artifact. |
| EWS access-control issue | Not created | The EWS package comparison changes only JARs and Debian changelog metadata.  No installed text artifact satisfies the extractor rule. |
| Mailbox-delegation authorization issue | Not created | The explicit `zm-mailbox` `GrantRights.java` change is Java, and the package boundary is JAR-only. |
| Nextcloud-integration SSRF | Not created | The non-patch Nextcloud package changes a JAR and ZIP payloads, not installed text; selected `zm-zimlets` also has no `10.1.20` tag. |

No package-backed source deletion was produced, and no added-only artifact was
treated as reconstructable source.
